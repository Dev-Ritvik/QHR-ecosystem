### C. The DB Connection Pool Deadlock (CRITICAL FIX)
* **The Bug:** The crawler uncovered a massive `500 Internal Server Error` cascade. Server Actions were opening transactions via `authedQuery`, and then calling `writeAudit`. `writeAudit` was internally calling `authedQuery` *again*, attempting to grab a second database connection. Under load, this exhausted the Supabase connection pool and caused a global deadlock.
* **The Fix:** Refactored `writeAudit` in `audit.ts` to accept an optional `tx` transaction parameter. 
* **The Codemod:** We wrote a Node.js codemod (`fix-audit.js`) to automatically inject the outer `tx` parameter into all `writeAudit` calls across all 18+ files in `apps/crm/src/server/actions/`.
* **TS Compilation:** The codemod caused some out-of-scope TypeScript errors. We wrote a custom parser script (`fix-tsc.js`) to read `tsc` output and surgically remove invalid `tx` parameters. The project now passes `tsc --noEmit` perfectly.
* **PostGIS:** Deployed a WKB parsing workaround to resolve PostGIS spatial type 500 errors on the `/pois` routes.
